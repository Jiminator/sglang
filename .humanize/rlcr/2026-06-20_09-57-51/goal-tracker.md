## IMMUTABLE SECTION
<!-- Do not modify after initialization -->

### Ultimate Goal

This is a **diagnosis loop, not a fix loop**. Produce a **root-cause verdict with live-measured evidence** explaining why table-free Double Sparsity (DS) token selection on GLM-5.1-FP8 is far less accurate than the native DSA indexer. Measured on the dev clone (`/sgl-workspace/sglang`, branch `dev/double-sparsity-standalone`, the default editable `import sglang`), GSM8K on 8×H200 TP=8, greedy temp 0, completion API:

| GSM8K | DSA (native) | DS (current table-free) |
|---|---|---|
| 5-shot / 200 — dense (~763 tok, seq < top_k 2048) | 0.970 | 0.625 (serial control 0.700) |
| 24-shot / 150 — sparse (~4.2k tok, seq > 2048) | 0.953 | 0.000 |

The deliverable is a **verdict plus the reusable reference selector built to find it** — explicitly NOT a fix. The verdict must localize the cause to exactly one (or a ranked combination) of:

- **H0** — the channel-selection algorithm does not transfer to GLM MLA (the accuracy ceiling is bad even with an exact, slow, optimization-free implementation).
- **H1** — a loop 6–12 performance optimization corrupts selection (the ceiling is good; one toggle regresses it; identify the toggle, its GSM8K cost, and the commit).
- **H2** — the offline channel mask is bad for GLM-5.1 (a sub-branch of H0).
- **H3 (added during planning)** — selection is fine; the regression is downstream of selection: the `logical_to_physical` → `transform_index_page_table_decode` index adapter, the selected-index set, or KV-slot validity (`_slot_written`), feeding the same `flash_mla_with_kvcache` decode kernel DSA uses.

Hard constraints (carry forward, never relitigate): run only the dev clone (`import sglang` must resolve to `/sgl-workspace/sglang`); never launch the v2 clone or set `PYTHONPATH` to a clone; never set `PYTORCH_CUDA_ALLOC_CONF=expandable_segments` for serving; one TP=8 server at a time (teardown + wait all 8 GPUs ~0 MiB before next boot); track the launched PID, never blanket-kill / `pkill -f`; `--disable-radix-cache` for DS; GSM8K via `--api completion`; **land no selection/adapter code fix this loop** — all new code is diagnostic only.

### Acceptance Criteria
<!-- Each criterion must be independently verifiable -->

Following TDD philosophy, each criterion includes positive tests (expected to PASS) and negative tests (expected to FAIL when the system is working correctly). All measurements run on the dev clone via the `development/loop13/` guarded scripts; one TP=8 server at a time. Full text of every AC (positive/negative tests, sub-criteria) lives in `development/loop13/plan.md` — this is the authoritative index.

- **AC-1: Pinned baseline reproduction.** DSA (native), a DSA-radix-OFF control, and current production DS reproduced on a fixed GSM8K sample set; production regression reproduced. Each arm records git SHA, model snapshot path, mask `content_sha256`, full server args, CUDA-graph on/off, eval sample IDs/order, `max_tokens`, concurrency, serial-vs-batched mode. Negative: `_env.sh` guard refuses non-dev-clone arms (rc=1); a DS arm that does NOT reproduce the regression halts the loop.

- **AC-2: Cheap localization controls and the H3 fork.** Before building the reference selector:
  - AC-2.1 — Dense forced-all downstream control (seq ≤ top_k emits logical `[0..seq_len-1]`); assert physical slots == `req_to_token[req_pool, 0:seq_len]`, no dup/`-1`/unwritten, adapter errors == 0. Recovery → scorer branch; still-bad with assertions passing → H3 (downstream).
  - AC-2.2 — TP head-aggregation micro-test: `local-max-per-rank then SUM-across-TP` vs `global-max` vs `global-mean` on captured per-head dots.
  - AC-2.3 — Selected-index equivalence: radix top-k == `torch.topk`; width `[5120]` vs `[]` identical. Retire suspects or promote on mismatch.
  - AC-2.4 — Recall-oracle recall@2048 recorded for dense+sparse as corroboration (not exoneration).

- **AC-3: Reference ("naive") selector served and proven faithful.** Performance-naive, algorithmically-faithful DS reference served via `serve.sh ref` (`selector_impl="reference"`), all selection-side perf optimizations off (fp8→fp32 dequant, exact full-width `torch.topk`, fp32 score-reduce, eager/`--disable-cuda-graph` allowed). Raw-dot uses existing fp32 absorbed scoring; cosine uses a materialized per-head signature.
  - AC-3.1 — Raw-dot reference (`absorbed_latent_score_logical`) == offline/blockwise materialized fp32 `K_label` (selected-index equality @2048).
  - AC-3.2 — Served cosine arm runs end-to-end and produces a real GSM8K number (normalize after mask-channel gather, Loop-7 lever).
  - AC-3.3 — DS-active invariants by regime: sparse `selected < total`, `dense_fallback == 0`; dense `selected == seq_len`.
  - AC-3.4 — Leak-free fp32: any GPU "fp32" reference disables TF32 or is explicitly labelled "GPU-fp32-with-TF32-risk".

- **AC-4: Per-arm GSM8K evidence table.** DSA, naive-DS (raw-dot), naive-DS (cosine), production DS on validated configs (5-shot/200 dense, 24-shot/150 sparse, temp 0, completion API), serial and batched. Each row: dense score, sparse score, serial/batched, radix on/off, selector width, score-reduce dtype/backend, head-agg mode, selected-vs-total, length-cap-garbage rate (invalid/unwritten/duplicate/out-of-range slot counts). Sub-5-point gaps require selected-index/recall corroboration.

- **AC-5: Decision gate.** Recorded with user-confirmed threshold: ceiling GOOD iff naive-DS (best of raw-dot/cosine) sparse 24-shot within 5 points of DSA AND not collapsed (> 0), AND dense within 3 points of DSA; else BAD. GOOD → AC-6; BAD → AC-7. Collapse (== 0) is BAD regardless of dense. Branch without recorded numeric gap rejected.

- **AC-6 (conditional — GOOD → H1): culprit isolated by single-variable bisection.** One variable per arm from reference toward production; GSM8K (dense+sparse) at each step until accuracy drops. Suspicion order: (1) `head_agg` shared-max-over-TP, (2) raw-dot vs cosine, (3) fp8 absorbed vs materialized fp32 `K_label`, (4) bf16 vs fp32 reduce, (5) approx vs exact radix top-k, (6) selector-width/W=5120. Prefer config toggles over git reverts. Culprit named with GSM8K cost + commit(s); each delta corroborated by recall/selected-index. Multi-variable steps rejected.

- **AC-7 (conditional — BAD → H0/H2): accuracy-ceiling knob sweep.**
  - AC-7.1 — No-mask ablation (full signature). Recovery → H2; still bad → H0.
  - AC-7.2 — Knob-response sweep (scorer raw/cosine; head_agg max/mean/per-head oracle; score_reduce fp32; selector_width full; top_k larger; mask recalibration; label_dim) with accuracy trend per knob; state whether ANY accuracy-favoring config recovers sparse to within 5 points of DSA.
  - AC-7.3 — Per-head selection reported as OFFLINE oracle upper bound (recall@2048 / would-be top-k), since the shared-set kernel cannot serve a per-head token set (DEC-1).

- **AC-8: Root-cause writeup** in `development/loop13/`: per-arm GSM8K evidence table, recall-oracle/selected-index corroboration, verdict (H0/H1/H2/H3 or ranked combination), recommendation (research vs targeted fix) — explicitly NOT a fix. Names exactly one primary hypothesis (or ranked set) tied to numeric evidence + negative controls. A writeup that proposes/lands a code fix is out of scope and rejected; a theory-only verdict (no live GSM8K number) is rejected.
