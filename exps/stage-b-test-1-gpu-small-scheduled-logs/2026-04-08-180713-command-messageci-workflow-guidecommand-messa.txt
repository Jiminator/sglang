  What the install script does (the big one)

  The full install script (scripts/ci/cuda/ci_install_dependency.sh) does these
  in order:

  1. Config: CU_VERSION=cu129, cudnn=9.16.0.29, nvshmem=3.4.5
  2. Detect GPU: auto-detect compute capability, set IS_BLACKWELL (5090 = SM120,
   so IS_BLACKWELL=1 since compute_cap >= 10.0). Uses pip (not uv) on Blackwell.
  3. Kill stale processes: python3 python/sglang/cli/killall.py
  4. APT packages: python3, pip, venv, dev, git, libnuma, libssl, ibverbs,
  ffmpeg + av libs
  5. Site hygiene: clear torchinductor cache, remove broken dist-info, install
  protoc
  6. Pip setup: upgrade pip, uninstall stale sgl-kernel/sglang/flash-attn
  7. Flashinfer version check: keep if version matches, uninstall if mismatch
  8. Install sglang: pip install -e "python[dev,runai,tracing]" 
  --extra-index-url https://download.pytorch.org/whl/cu129
  9. Install sglang-kernel: from PyPI (normal) or wheel artifact (if kernel
  changed)
  10. Install sglang-router
  11. Download flashinfer jit-cache and cubin artifacts
  12. Extra deps: mooncake, nvidia-cuda-nvrtc-cu12, py-spy, scipy,
  huggingface_hub[hf_xet], pytest. On Blackwell: skips lmms-eval. Uninstalls
  xformers.
  13. Fix deps: reinstall torchaudio/torchvision if CUDA version mismatch, pin
  nvshmem, pin cudnn, force-reinstall cutlass-dsl, download kernels community,
  install human-eval
  14. Prepare runner: cleanup HF cache, prevalidate cached models

  How the test is actually invoked

  run_suite.py partitions the tests, then for each test file calls:

  The -f flag enables unittest failfast mode. With retry enabled (default for

  ---
  How to Reproduce Locally

  Since you're already on this machine with the repo, here's what to do. The CI
  runs inside a Docker container with CUDA pre-installed, and sources
  /etc/profile.d/sglang-ci.sh (runner-specific). Locally, you need to
  approximate that.

  Step 1: Set environment variables

  export SGLANG_IS_IN_CI=true
  export SGLANG_CUDA_COREDUMP=1
  export SGLANG_JIT_DEEPGEMM_FAST_WARMUP=true

  Step 2: Install dependencies (the same script CI uses)

  # From repo root:
  CUSTOM_BUILD_SGL_KERNEL=false bash scripts/ci/cuda/ci_install_dependency.sh

  This is the exact same script CI runs. CUSTOM_BUILD_SGL_KERNEL=false tells it
  to install sgl-kernel from PyPI (the normal path when kernel code hasn't
  changed).

  Note: This script runs set -euxo pipefail and calls apt-get, so it needs root.
   It will also kill existing GPU processes. If /etc/profile.d/sglang-ci.sh
  doesn't exist on your machine, create an empty one or skip sourcing it in the
  workflow step — the install script doesn't source it itself.

  Step 3: Run the exact same test the CI runs

  Option A — Run the full partition 5 (all tests that run alongside your test):

  cd test/
  python3 run_suite.py --hw cuda --suite stage-b-test-1-gpu-small \
      --auto-partition-id 5 --auto-partition-size 8

  Option B — Run just the flaky test file directly (same as CI invokes it):

  python3 test/registered/models/test_transformers_models.py -f

  Option C — Run only the specific flaky test class+method:

  python3 -m pytest test/registered/models/test_transformers_models.py::TestTran
  sformersFallbackTorchAO::test_mmlu -v

  Or with unittest:
  python3 -m unittest test.registered.models.test_transformers_models.TestTransf
  ormersFallbackTorchAO.test_mmlu

  The flaky test itself

  Looking at TestTransformersFallbackTorchAO.test_mmlu — it launches a server
  with --model-impl transformers --torchao-config int4wo-128, runs 64 MMLU
  examples, and asserts score >= 0.63. This is a quantized model accuracy test —
   it's inherently flaky because int4 quantization introduces variance, and the
  MMLU subset of 64 is small enough that score can fluctuate around the
  threshold. This is exactly the kind of failure CI classifies as "retriable"
  (matches score and AssertionError patterns).
